# Текущие режимы проекта

Этот документ фиксирует **текущее состояние проекта**: какие режимы уже реализованы, как они соотносятся друг с другом и где именно применяются.

Планируемые режимы сюда не включаются.

## 1. Режимы генерации задачи

Режим генерации хранится в `ProblemInstance.generation_mode`.

### `random`

Базовый учебный режим.

Что делает:

- генерирует случайные уникальные `prices`;
- генерирует скрытый бинарный вектор `hidden_vector`;
- считает `target_sum = dot(prices, hidden_vector)`;
- отбрасывает инстансы без уникального точного решения.

Когда использовать:

- для отладки;
- для демонстрации алгоритма;
- для быстрых smoke-тестов.

### `superincreasing_disguised`

Основной тяжёлый режим для benchmark.

Что делает:

- строит супервозрастающую последовательность;
- маскирует её через модуль, множитель и перестановку;
- формирует более сложный публичный инстанс для поиска.

Когда использовать:

- для честного сравнения режимов ГА;
- для benchmark;
- для задач, где обычный `random` слишком лёгок.

## 2. Режимы solver

Режим solver задаётся через `GeneticAlgorithmConfig.solver_mode`.

### `classic`

Базовый режим solver.

Что делает:

- запускает один проход обычного ГА;
- поддерживает обычную остановку по:
  - `exact_match`
  - `stagnation`
  - `generation_limit`
- может один раз вызвать `NGA`, если выбран один из `nga_mode != none`.

Когда использовать:

- для основного CLI-запуска;
- для benchmark текущих `NGA`-режимов;
- для сравнения обычного ГА и одноразовых вмешательств.

### `restart_rescue`

Отдельный режим solver с полными рестартами и одним rescue-этапом.

Что делает:

- запускает обычный ГА;
- при стагнации сохраняет глобально лучший результат;
- делает новый полный запуск с новой случайной популяцией;
- повторяет полные рестарты, пока каждый следующий запуск строго улучшает `difference`;
- при первом неулучшающем запуске выполняет ровно один rescue-этап;
- если rescue не помогает, возвращает лучший накопленный результат.

Особенности:

- это отдельный `solver_mode`, а не `nga_mode`;
- в этом режиме `nga_mode` должен быть `none`;
- в этом режиме `repeat_limit` не используется.

Типичные причины остановки:

- `exact_match`
- `generation_limit`
- `restart_limit`
- `rescue_stagnation`
- `rescue_generation_limit`

Когда использовать:

- когда нужен более агрессивный поиск через независимые запуски;
- когда одноразового `NGA` в рамках одной популяции недостаточно.

## 3. Режимы `NGA` внутри `classic`

Режим `NGA` задаётся через `GeneticAlgorithmConfig.nga_mode`.

Он работает только при:

- `solver_mode = classic`

### `none`

Базовый ГА без дополнительного вмешательства.

Что делает:

- работает как обычный ГА;
- останавливается по точному совпадению, стагнации или лимиту поколений;
- `repeat_limit` в этом режиме не используется как обязательный параметр.

### `two_point`

Одноразовый `NGA-1`.

Когда срабатывает:

- если в `classic`-режиме достигнут `repeat_limit` без улучшения;
- срабатывает только один раз за запуск.

Что делает:

- формирует одно специальное поколение;
- использует двухточечный кроссовер;
- использует двухточечную мутацию;
- после этого возвращается к обычному ГА.

### `elite_heavy_mutation`

Одноразовый `NGA-2`.

Когда срабатывает:

- если в `classic`-режиме достигнут `repeat_limit` без улучшения;
- срабатывает только один раз за запуск.

Что делает:

- сохраняет лучшую особь;
- остальные особи сильно мутирует;
- число инвертируемых битов задаётся через `nga_mutation_fraction`;
- после этого возвращается к обычному ГА.

## 4. Что общего у всех текущих режимов ГА

Независимо от режима:

- особь представляется бинарным вектором;
- fitness сейчас равен `difference = abs(target_sum - current_sum)`;
- селекция родителей турнирная;
- базовый кроссовер одноточечный;
- базовая мутация инвертирует один случайный бит;
- в поколение переносится элита;
- локальный отбор потомков идёт по схеме:
  - из `parent_a`, `parent_b`, `child_a`, `child_b`
  - выбираются лучшие 2 особи
  - они и переходят дальше.

## 5. Какие параметры относятся к каким режимам

### Общие параметры

Используются почти везде:

- `population_size`
- `generations`
- `stagnation`
- `crossover_rate`
- `mutation_rate`
- `tournament_size`

### Параметры только для `classic + NGA`

- `nga_mode`
- `repeat_limit`
- `nga_mutation_fraction`

### Параметры только для `restart_rescue`

- `solver_mode = restart_rescue`
- `restart_max_count`
- `rescue_min_mutated_bits_ratio`

## 6. Какие режимы benchmark использует сейчас

Текущий benchmark работает только с режимом:

- `solver_mode = classic`

И сравнивает три `algorithm_mode`:

- `none`
- `two_point`
- `elite_heavy_mutation`

По умолчанию benchmark:

- использует генератор `superincreasing_disguised`;
- не использует `restart_rescue`;
- не включает планируемые режимы, которых ещё нет в коде.

## 7. Какие stop reason реально есть сейчас

### Во внешнем результате `classic`

- `exact_match`
- `stagnation`
- `generation_limit`

### Во внутреннем single-run

- `exact_match`
- `stagnation_limit`
- `generation_limit`

### Во внешнем результате `restart_rescue`

- `exact_match`
- `generation_limit`
- `restart_limit`
- `rescue_stagnation`
- `rescue_generation_limit`

## 8. Что важно не путать

### `solver_mode` и `nga_mode`

Это разные уровни:

- `solver_mode` определяет общую схему поиска;
- `nga_mode` определяет одноразовое вмешательство внутри `classic`.

### `restart_rescue` и `NGA`

`restart_rescue`:

- это самостоятельный режим solver;
- он не является `NGA`;
- он не использует `repeat_limit`;
- он не должен комбинироваться с `two_point` или `elite_heavy_mutation`.

### Планируемые режимы и текущие режимы

В проекте уже есть:

- `classic`
- `restart_rescue`
- `none`
- `two_point`
- `elite_heavy_mutation`

В проекте пока нет:

- новых многошаговых `NGA`-режимов со срабатыванием в нескольких точках стагнации.
